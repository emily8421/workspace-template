# 通用-文档评估规范

> **用途**：规定开发过程文档的评估维度、流程、输出格式和处置方式。用户说「评估 XX 文档」时，按本规范执行对应类型的全维度评估；指定某一维度或小点时，只评估所指内容。
> **适用范围**：正式工程文档——需求、设计（含图表）、计划、规范、评审与裁定材料、版本记录与状态类管理文档。历史归档区只读，不评估。
> **不适用**：可行性评估（技术/资源/排期可行性由项目阶段机制承载，不属文档评审）；编码产物（走编码规范）。

## 1. 评估维度（11 项）

| # | 维度 | 查什么 | 主要方法 |
|---|---|---|---|
| D1 | 内容完整性 | 对照上游批准口径与文档应有要素，查缺口；有行业标准/模板结构时对照 | 对账：上游基线逐项核对 |
| D2 | 逻辑正确性 | 节间/表间/矩阵内部口径自洽；概要表与明细矩阵逐环节对应；与既有机制（门禁/角色/流程）不矛盾 | 交叉核对 |
| D3 | 无歧义性 | 边界词（较多/相近/当天）有判定口径：谁判、按什么判 | 逐条追问 |
| D4 | 跨文档一致性 | 同一口径在多文档同步（单一事实源）；重点查最近变更的联动面 | 对账式协审 |
| D5 | 可追溯性 | 编号链双向完整：条目有上游来源、有下游引用 | 编号抽查 |
| D6 | 可验证性 | 每条可判定通过/失败；量化条件（数值/口径）落位；NFR 重点 | 逐条问「怎么验收」 |
| D7 | 必要性 | 每条可溯源到用户需求或强制约束，无开发方自加（镀金） | 溯源抽查 |
| D8 | 分级清晰度 | 批次/优先级/版本的标记处处可辨，不混写 | 通读标注 |
| D9 | 语言规范性 | 全局规则「文档语言与表达规范」逐条（含机器文风特征，机扫清单见本文附录） | 机扫+人工 |
| D10 | 状态时效性 | 状态词、版本声明、快照类内容与文档实际状态一致（批准基线内不得残留评审期状态词，如「拟冻结」「待评审」） | 对照版本记录 |
| D11 | 引用完整性 | 路径引用不断链、编号引用可定位（目录重组/文件移动后必查）；表格编号无重复 | 全仓 grep 校验 |

**可行性（技术/数据/排期）不列入**：由项目阶段机制承载。

## 2. 按文档类型的维度侧重

| 文档类型 | 全维度之外的重点 | 可简化的 |
|---|---|---|
| 需求类 | 全部 11 项 | — |
| 设计类（含图表） | D2/D4/D5/D11（图表画法另见图表建模规范） | D6 留测试文档 |
| 计划/台账/状态类 | D4/D10/D11（状态时效最关键） | D3/D6/D7 |
| 评审与裁定材料 | D2/D4/D10（结论与记录表一致） | D6 |
| 规范类 | D4/D10 | D5 |

## 3. 评估流程（五步）

1. **定事实源**：识别该文档的上游批准基线、关联台账、版本记录，取最近变更 diff（git）。增量修订最易引入违例，最近变更区是人工复核重点。
2. **机扫**：按附录 pattern 全文扫描（术语残留/高频词/直译句式/弱强度词/过时状态词/编号重复）。
3. **人工复核**：通读全文，按维度清单逐项核对；重点覆盖机扫够不到的 D1～D6（长链句、表格混排、口径错位、联动缺位）。
4. **出差异清单**：结论先行（总体判定+发现数），符合项简表，差异项逐条编号并分级：
   -【必修】违反强制条款或存在事实错误/断链/矛盾；
   -【建议修】有依据条款、不改不致错但降低质量（术语漂移、结构混乱）；
   -【可选】观感/格式类，改不改两可；
   -【留痕不动】已知且有机制覆盖的残留（如存量旧术语、历史文档内引用），说明依据即可。
   每条含：定位（行号/章节）、问题描述、依据（维度+条款）、建议改法。
5. **裁定与执行**：用户裁定分级处置后执行；登记与提交遵循第 5 节。

## 4. 输出格式

- 结论先行：一句话总体判定+发现分布（必修/建议/可选各几项）。
- 符合项：表格，简短（维度+核对对象+结果）。
- 差异项：编号（发现 1、发现 2……），按必修→建议→可选排序。
- 处置建议：给默认建议方案，等用户裁定；不代替用户决策。

## 5. 处置与登记

| 修订性质 | 判据 | 处置 |
|---|---|---|
| 表述级勘误 | 不改需求内容与口径：语言、术语同步、结构重组（内容等价）、编号修正、状态词清理 | 在当前版本内落，不升版；版本记录该版行补勘误注记；基准结论不变 |
| 一致性补齐 | 同步已批准口径到滞后文档（指针化，不新增决策） | 同上，版本记录注明「一致性补齐」 |
| 内容变更 | 新增/修改需求内容或口径 | 按项目变更机制登记后升版，不直接改批准文本 |

## 附录 · 机扫 pattern 清单（随实践追加）

| 目的 | pattern（正则） | 备注 |
|---|---|---|
| 空洞高频词 | `沉淀|收口|抓手|赋能|拉通|对齐了|旅程|一体化|底座|旨在|致力于|深度整合|强有力|值得一提` | 判据：删除后信息不减 |
| 直译句式/弱强度词 | `不仅.{0,20}更|值得注意的是|的关键所在|尽量|必要时|适当` | 单独使用无检查标准即违例（语言规范） |
| 过时状态词 | `拟冻结|待评审|工作版本|待复验`（对照版本记录实际状态） | 批准基线内残留即 D10 违例 |
| 编号重复 | 表格 `#` 列重复值 | 表格编号唯一性 |
| 引用断链 | 被移动/改名文件的旧路径全文 grep | 重组后必查；历史文档内残留按换算表豁免 |
| 半角波浪号范围号 | `~`（U+007E）用作范围号（如 F-001~007） | 部分渲染器将成对 `~` 解析为下标，范围尾部数字变下标；范围号一律用全角 `～`（本行示意字符保留半角，勿批量替换） |
| 实例术语基线 | 按实例术语表自定 | 例：委托方与下游客户的称谓区分；实例建立后追加本行 |

**判据总则**：可验证信息是否因该词/句/标注的存在而增减——不减即删；口径与事实源逐字核对，差异列清单给人裁定（对账式协审）。
