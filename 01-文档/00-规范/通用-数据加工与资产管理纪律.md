# 通用-数据加工与资产管理纪律

> **用途**：有数据加工环节的实例（原始数据→整理→装载→运行期）适用：数据资产怎么分级来源、怎么沉淀、出问题怎么处置、表结构怎么给未来留位。纯文档型实例可以不用本规范。
> **定位**：只规定组织纪律，不规定具体表结构与存储设计（那属于项目设计文档）。

## 1. 资产来源分级（四档）

各数据资产的获取方式分四档，规划生产前先归档：

| 来源档位 | 获取方式 | 启动瓶颈 |
|---|---|---|
| 直接装载 | 原件登记后即可使用，仅作轻量校验 | 随原件到位 |
| 抽取加工 | 按固定规则从原材料提取，可自动执行和重跑 | 随批量推进 |
| 分析沉淀 | 工具产出候选，经人工核验或审核后成立 | 取决于人工审核资源 |
| 运行期自产 | 系统运行中产生，不来源于原始数据 | 部署后才发生 |

使用约束：

1. **不得把运行期自产资产当作可从原始数据抽取的内容来规划生产**（自产数据在部署前不存在，无法提前「抽取」）。
2. 分级说明获取方式的对应关系，不代表执行的先后顺序。

## 2. 批次纪律

1. **初始装载只有一条合法入口**：数据整理验收后的冻结批次交接。绕过批次登记的直接拷贝无效。
2. 日常增长按固定路径沉淀，全程由问题台账与操作记录覆盖。
3. 每次对外发布形成新批次，不覆盖旧批次；任何分析结论必须标注所用批次标识与规则版本。
4. **历史处理产物只作对照，不得作为正式基准**——正式基准以现行批次的登记为准。

## 3. 质量与问题纪律

1. 原始材料一律只读；入库时登记来源、版本、获取时间和校验值。
2. 未通过准入检查的数据必须形成问题记录，含问题依据、建议动作和责任角色；**禁止静默丢弃**。
3. 人工补充和裁决写入专门记录表并复核；不得直接修改原始文件或抽取层关系表。

## 4. 预留槽位模式

任务级、项目级实体的表结构应为将来可能新增的证据类型预留三类占位字段：`source_type`（来源类型）、`status`（存在状态）、`evidence_ref`（证据引用）。

尚未到位的材料（如需求规格、设计方案、用例）按默认值占位（如 `not_provided`）：**缺位不是缺陷，不得据此阻断功能**；但必须在查询结果中可见可查。材料到达后填槽生效，无需变更整体结构。
