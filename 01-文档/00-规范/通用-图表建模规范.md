# 通用-图表建模规范

> **用途**：规定开发过程文档中模型图的画法——图型与工具选择、要素、拆分粒度、命名与工具语法。画图（AI 或人）时按本规范执行；评审图表时配合 `通用-文档评估规范.md` 的逻辑正确性与引用完整性维度使用。
> **适用范围**：开发过程文档中全部模型图（需求/设计/计划/规范文档内嵌图）。历史归档区图表不追溯套用。
> **与其他规范的分工**：项目阶段规范规定「何时必须有图」（用例图/类图等配置），本规范只管「怎么画」。
> **来源**：UML 2.5 规范（OMG）通行做法与实例图表实践提炼；附录 A 各条均为实测坑（2026-08 两轮渲染事故验证）。

## 0. 图型与工具的默认选择

| 图型 | 默认工具 | 理由 |
|---|---|---|
| 用例图 | **plantuml** | mermaid 无 usecase 图型（唯一选择）；引号内标签不写真实换行（附录 A2） |
| 类图（分析/设计） | **mermaid** | VS Code/GitHub 原生预览零配置；分组用 namespace（附录 A5）、多重度写引号标签（A1） |
| 顺序图/时序图 | **mermaid** | `sequenceDiagram` 语法成熟、预览友好 |
| 状态图 | mermaid | `stateDiagram-v2` 够用 |
| 结构图/ERD | mermaid 优先 | 同上；ERD 可由分析类图等价承担 |

选型总则：**能在目标阅读环境直接渲染的优先**（VS Code 预览/GitHub 渲染）；同一图型在同一文档内不得混用两种工具；迁工具（mermaid↔plantuml）须在所属文档版本记录登记理由。

## 1. 通用规则（所有图型适用）

| # | 规则 | 依据/理由 |
|---|---|---|
| G1 | **一图一主题**：每张图只回答一个问题（系统做什么/结构怎么分/对象怎么交互）。一张图试图同时回答两个问题时拆开 | 可读性；评审无法对一张图给出单一结论 |
| G2 | **7±2 上限**：一张图内主要元素（用例/类/状态）超过 9 个时必须拆分或分组；拆分维度优先级=按参与者 > 按业务包 > 按子系统 | 认知负荷；UML 教材通行做法 |
| G3 | **唯一编号**：图内元素凡被正文/台账/测试引用，必须带稳定编号（如 UC-xx、DS-xx）；图拆分不改变元素编号，只改呈现分组 | 引用链完整性 |
| G4 | **图题三要素**：图名 + 版本 + 日期，写在图标题或紧邻引言；图变更随所属主文档版本登记，不单独立版本记录 | 单一事实源 |
| G5 | **术语一致**：图内元素名与术语表/正文严格同名；中文名优先，确需英文标识符（如类名）时保持「英文标识符+中文标签」并用注释锚定语义 | 语言规范术语纪律 |
| G6 | **图例必写**：使用非标准记法（如系统内参与者、边界外人工环节注记）时，图旁必须写图例说明；标准 UML 记法不必解释 | 非标准记法读者无从解码 |
| G7 | **正本与副本**：图的正本（源码块）与展示副本（渲染 PNG）分离——正本为准，副本随正本重渲染；副本声明指向正本 | 单一事实源 |

## 2. 用例图

### 2.1 要素规则

| 要素 | 规则 |
|---|---|
| 系统边界 | 一张图一个边界框；拆多张图时每张图画各自边界（同一系统的不同视图，合法） |
| 参与者（actor） | 边界外；人形符号。**外部系统**画 actor 或画边界外系统框均可，同一文档内选一种并用图例声明 |
| 系统内参与者 | 系统内组件需要出现在图上时画在边界内并加注「系统内」；这是合法但少见的记法，**不得省略图例说明**（G6） |
| 用例 | 椭圆，边界内；动宾短语命名（「检索候选」而非「检索」） |
| 关系 | 关联（实线）、`<<include>>`（必经子用例）、`<<extend>>`（条件扩展）、泛化；一张图内连线超过约 30 条视为超限信号，按 G2 拆 |
| 编号 | UC-xx 系列与正文用例表一一对应；扩展用例用主编号+字母后缀（UC-04a） |

### 2.2 拆分规则

1. **总览优先**：用例总数 ≤9 且参与者 ≤4 时用一张全图。
2. **超限拆分**：按**主要参与者**拆（每类主要参与者一张「该视角的用例图」），另保留一张**总览图**（只画参与者与一级用例，不画 include/extend 细节），防止碎片化。
3. **同一用例跨图**：允许在多张图出现，编号不变；总览图负责消歧。
4. 用例较多但连线密集而评审未反对时，可维持一张全图，**必须**在图例声明密度取舍；后续新增用例触发拆分。

## 3. 分析类图（领域对象模型，需求阶段）

| 要素 | 规则 |
|---|---|
| 粒度 | 分析级：类名+关键属性（分析粒度，不定义可见性/方法签名）；完整字段归设计阶段数据对象模型 |
| 实体来源 | 取自数据词典、数据描述、场景规格；**不得凭空新增无锚点实体** |
| 关系 | o--（聚合/组成实线）、-->（引用）、..>（依赖/使用）；中文关系标签必写（标注语义与依据编号） |
| 超限分组 | 实体超过 7±2 上限时**优先用分组呈现**（按业务域框住，关系线跨组照画，一张图不拆页）——类图实体关系网状，物理拆图会断关系链；分组豁免须在图例声明分组依据 |
| 新概念回填 | 裁定/变更引入的新概念必须在下一次该图升版时补入——实体缺席=需求与模型脱节 |
| 英文类名 | 允许（分析对象标识符）；改英文类名会断下游图表引用时留痕不动，在图例注明中英映射 |

## 4. 设计类图（概设/详设阶段）

| 要素 | 规则 |
|---|---|
| 粒度 | 设计级：属性带类型与可见性、方法带签名；与代码模块一一对应 |
| 分层 | 概设级画模块（职责+接口概貌）；详设级画类（成员完整）；**详设不改概设的职责边界，只细化** |
| 关系 | 同分析类图记法，另可加实现（`..|>`）与泛化（`--|>`）；继承深度建议 ≤3 层 |
| 与分析类图追溯 | 每个设计类应能指回分析类或说明新增理由；分析类消失时必须在版本记录登记原因 |

## 5. 交互图（顺序图/时序图）

| 要素 | 规则 |
|---|---|
| 用途 | 用例的主流程/关键异常必须可画成顺序图；顺序图的生命线=设计类或系统组件 |
| 数量 | 只为**主链用例**画，不要求全用例覆盖 |
| 分屏 | 一张顺序图超过 ~15 条消息时按阶段拆（如「校验」「执行」两张），用连续编号标记 |
| 异常 | 异常分支用 alt/par 片段框，不与主流程混画在同一泳道层级 |

## 6. 其他图型（按需适用）

| 图型 | 场景 | 最小规则 |
|---|---|---|
| 系统结构图 | 总体结构 | 分层框图；每框=模块/服务；连线=调用或数据流，加中文标签 |
| ERD | 数据库/存储设计 | 与数据词典编号互指；分析类图可等价承担 ERD |
| 状态图 | 对象生命周期复杂时 | 状态命名与状态字典严格同名；迁移条件写在迁移线上 |
| 事物—事件表 | 用例↔类图桥梁 | 编号列唯一 |

## 附录 A · 工具语法约束（mermaid / plantuml，均为实测坑）

| # | 约束 | 依据 |
|---|---|---|
| A1 | mermaid 类图内**禁用 PlantUML 多重度记法**（`}o--||`/`||--o|` 等触发解析错误 `Unrecognized text`）；多重度写进关系标签（`"1" o-- "many"` 形式的引号标签写法经验证可用） | 实例关系行批量修复实践 |
| A2 | plantuml 需要两行显示的标签（actor/用例名）：源码内写**字面反斜杠 n 序列**，不写真实换行（部分渲染器按截断报错）；AI 批量改写图源码时，字符串替换的目标须按「反斜杠字符+n 字符」两个字面字符匹配，不得用换行转义去匹配真换行，否则会误删整段源码换行 | 实例两轮实践（含一次误删事故，从 git 恢复） |
| A3 | mermaid 块内不使用全角括号外的中文标点做语法分隔；注释用 `%%` | 渲染兼容 |
| A4 | 图源码块使用 ```plantuml / ```mermaid 围栏标注，渲染工具按围栏选择；正本在源码块内，渲染产物为副本（G7） | 正本副本分离 |
| A5 | mermaid classDiagram **不支持 `package` 关键字**（中英文名均报 Lexical error）；分组用 **`namespace`**（中文名可用） | 实例三组对照实测：package 全失败、namespace 全通过 |
| A6 | mermaid classDiagram **关系线标签（`: label` 部分）内禁用半角冒号 `:` 与半角括号 `()`**（`1:N` 的冒号触发解析错误；类成员行内括号不受限）；标签内多重度写「1对N」或全角括号 | 实例概设图表实测 |

> 既有已批准图表不追溯重画，随其所属文档下一次升版时按本规范核对。
