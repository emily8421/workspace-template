## 二、逐项说明

### 1. 工具管理机制（价值最高）

**问题**：模板对脚本治理完全空白。实例在无机制状态下出现过：重复开发同类脚本、误用绑定历史快照的旧脚本、脚本/数据/正式文档混放、临时脚本散落。

**机制**（提炼自实例 `07-工具管理.md`，去实例路径）：

- **唯一登记源**：`04-工具/tool-registry.json`，登记字段至少含：ID、名称、范围（公共/专用）、生命周期、输入输出契约、风险、运行限制、最小命令、验证方式、最后验证日期。`tool-registry.md` 为自动生成的人读视图，禁止手改。
- **先检索后新建**：新建/调整脚本前必须先检索注册表（人读视图或 `find-tool.ps1 -Keyword`）。
- **生命周期五态**：`草稿`（不得作新任务入口）→ `现役`（唯一可用态）→ `冻结`（绑定固定历史输入）→ `历史`（仅追溯证据）→ `废弃`（禁止执行）。脚本「仍可运行」不等于可复用。
- **登记判据**：可跨阶段复用 / 生成正式产物或决策证据 / 修改复制下载数据 / 需由他人发现复跑维护——满足任一即必须登记。
- **临时脚本边界**：一次性脚本及其日志缓存只放系统临时区（`<系统约定临时根>/<实例名>/<YYYYMMDD>-<任务简称>/`），不登记、不作正式文档长期链接入口；同类临时脚本第二次被需要时必须参数化并按正式流程登记。
- **配套脚本**（随 `04-工具` 骨架复制）：`find-tool.ps1`（检索）、`validate-tool-registry.py`（登记源校验）、`render-tool-registry.py`（人读视图生成）、空 `tool-registry.json`。

**回流方式**：模板新增 `_workspace/09-工具管理.md`（只含机制，生命周期表与登记流程通用化），`00-总入口.md` 读取顺序补 09；`04-工具` 骨架补脚本与空注册表；`create-instance.ps1` 复制清单相应扩展。

**注意**：实例的具体工具条目（GitLab 同步、OSS 下载、spec 拉取等）与专用工具路径（`01-文档\...\02-分析工具\`）不回流。

### 2. 保护注册清单三层机制

**问题**：模板 02 的保护目录是简单路径列表，无例外粒度、无机器可读形态。实例演化出三层：

1. **人读注册清单**（唯一真相）：字段含路径 / 保护级别 / **例外可写项** / 依据。例外可写项解决简单只读表达不了的边界（如「分析产物只读，但脚本与索引治理元数据可维护」）。
2. **机器镜像** `protected-paths.json`：批量/整理脚本排除路径一律读镜像、不得硬编码；镜像与清单同步维护。
3. **编辑器软保护**：`.code-workspace` 的 `files.readonlyInclude` 按清单主要数据本体路径配置；明确「软保护非强制，规则以清单为准」。

**回流方式**：模板 02 的「保护目录」节升级为注册清单表式（含例外可写项列），补 JSON 镜像与软保护两层说明及同步维护约定。`protected-paths.json` 空结构随 `04-工具` 骨架复制（或与回流项 1 的工具治理目录合并落地）。

**已知局限（须一并写入模板）**：多根工作区下 `readonlyInclude` 对「整目录根」不生效；仅防误触，不构成强制约束。

### 3. 文档语言与表达规范

**问题**：AI 生成正式工程文档时易出现空泛口号、术语漂移、把假设写成结论、强度词不可检查等通病；各实例各自摸索约束，无通用基线。

**内容**（实例已验证有效，8 条）：平实书面语、术语准确稳定、一句一个主要判断、抽象术语须附具体对象与可验证结果、事实/假设/候选/待确认明确区分、强度词规范（`必须`/`不得`/`应`/`可以`/`建议`/`待确认`）、非技术读者场景例外、生成后自检清单（口号/长句/术语漂移/无依据评价/冗余句）+ 典型改写对照表。

**回流方式**：整节并入 `_workspace/08-通用文档管理原则.md`（新增 A7 或独立章节），`sync: auto`。与 A1-A6 同级通用，不含任何业务内容。

### 4. 外部数据根登记模式（示例，不进规则）

实例为实例目录树之外的数据盘（`E:\miiot-data`）建立了完整登记模式：数据根 README + `索引/` 清单 + `AGENTS.md`/`CLAUDE.md` AI 入口（链回实例 00-总入口）+ 挂载登记（绝对路径）+ 保护注册清单行 + 「数据盘不得作为可执行脚本长期入口」边界。

实例续接文档（20260813 治理收口）已预留：「若出现第二个外部数据根，再把 E盘入口模式模板化」。

**回流方式**：`_workspace/_参考示例/外部数据根登记-示例.md`，去业务字段（目录名/包数/具体盘符换占位符），标注「示例，非规则」。与现有 C1-C3 示例同级。

### 5. settings 基线版本化 + 软保护说明（小补丁）

- `.code-workspace` 位于实例根，实例根通常非 git 仓（拓扑 A）；其 `settings` 段无人版本管理，易漂移丢失。实例做法：在挂载登记（`06`/模板 `07`）中加「settings 基线」小节做版本化记录，约定「手改 settings 时同步更新本节」。
- 同时补 readonlyInclude 局限与「软保护非强制」注意事项（与回流项 2 联动）。

**回流方式**：模板 `_workspace/07-VSCode工作区挂载登记.md` 补「settings 基线（版本化记录）」小节模板与注意事项。

## 六、通用性评估结论（2026-08-17，已按此落地）

> 评估框架沿用 20260808 版分层（A 通用原则→规则 / B 空表单→`_表单` / C 业务示例→`_参考示例`）与「复制即用 + 最小骨架」定位。
> **结论：5 项全部为机制、可回流；其中 2 项按「采纳机制、瘦身实现」落地**（配套重量收紧，保住模板最小骨架定位）。

### 6.1 判定总表

| # | 机制 | 通用性 | 判定 | 落地形态 |
|---|---|---|---|---|
| 1 | 工具管理机制 | 中高 | ✅ 采纳机制，⚠️ 瘦身配套 | `09-工具管理.md`（规则，sync: auto）+ 空注册表 + 仅留 PowerShell 检索脚本；validate/render 脚本不随骨架复制 |
| 2 | 保护注册清单三层 | 高 | ✅ 采纳第一层，镜像/软保护降级 | 02 升级清单表式（含例外可写项）；机读镜像记为可选（仅批量脚本实例自建）；编辑器软保护记为可选 + 局限说明 |
| 3 | 文档语言与表达规范 | 最高 | ✅ 全量采纳 | 08 新增 A7（sync: auto，紧凑版） |
| 4 | 外部数据根登记模式 | 中 | ✅ 示例级采纳 | `_参考示例/外部数据根登记-示例.md`（占位符化，标注示例非规则） |
| 5 | settings 基线版本化 + 局限 | 中 | ✅ 小补丁采纳 | 07 补 settings 基线小节；readonlyInclude 局限写入 02 |

### 6.2 判定要点

- **#1 工具管理**：机制自校准（登记判据满足任一才登记，纯文档实例注册表自然为空），通用性成立；但配套三件套（find/validate/render）混合语言、强加 Python 依赖，与模板纯 PowerShell 工具栈（create-instance/sync-template/sync-vscode-workspace）冲突。**瘦身**：只随骨架复制空 `tool-registry.json` + `find-tool.ps1`，validate/render 省略并注明「注册表 JSON 即唯一源，校验/人读视图按实例需要自建」。
- **#2 保护清单**：第一层（人读清单表式 + 例外可写项）解决通用边界（整树只读表达不了「树内治理文件可写」），便宜且真通用；JSON 镜像的价值依赖「实例有批量脚本消费」——通用模板无消费方，强制维护 = 负担 + 漂移风险；编辑器软保护在模板目标拓扑（多根 .code-workspace）下对整目录根不生效，收益有限。
- **#3 语言规范**：纯机制、零业务内容、命中模板核心职责（文档管理），最干净，全量采纳。
- **#4 外部数据根**：拓扑相关需求（多数实例没有），进规则会污染；作示例零成本；内嵌边界「数据盘不得作可执行脚本长期入口」已由 #1 临时脚本边界 + A5 覆盖，无需单列。
- **#5 settings 基线**：问题是真实的（拓扑 A 下实例根非 git，settings 无版本管理、易漂移）；07 为 sync: manual 实例文件，加一小节是文档约定、零风险。

### 6.3 与提案原文的差异（瘦身项）

| 提案原文 | 评估后落地 | 原因 |
|---|---|---|
| 配套脚本 find-tool.ps1 + validate-tool-registry.py + render-tool-registry.py 随骨架复制 | 仅 `find-tool.ps1`（PowerShell）+ 空 `tool-registry.json`；validate/render 省略 | 保持纯 PowerShell 工具栈，避免给每个新实例强加 Python 依赖 |
| protected-paths.json 随骨架复制 | 不强制复制；仅在实例启用批量脚本时于工具治理目录自建 | 通用模板无镜像消费方；镜像与清单同步维护属条件需求 |
| `.code-workspace` 软保护随清单升级为模板规则 | 记为可选 + 写明局限（多根工作区整目录根不生效、软保护非强制） | 模板目标拓扑下收益有限，且规则以清单为准 |
