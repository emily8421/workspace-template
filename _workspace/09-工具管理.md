# 工具管理（脚本/可执行资产治理）

> 适用：`04-工具/` 与实例内任何可执行脚本。机制通用化，不含实例业务工具条目（模板预登记的 5 条治理脚本除外）。
> 配套：注册表 `04-工具/tool-registry.json`；检索 `04-工具/find-tool.ps1`；校验与渲染 `04-工具/00-工具治理/`；挂载与续接索引脚本 `04-工具/03-工作区治理/`。

## 为什么需要

无机制时反复出现：重复开发同类脚本、误用绑定历史快照的旧脚本、脚本/数据/正式文档混放、临时脚本散落。

## 唯一登记源与维护流程

- `04-工具/tool-registry.json` 为**唯一登记源**。每条登记至少含：ID、名称、范围（公共工具/分析专用工具/历史工具）、生命周期、执行策略（如备份先行/校验中止/幂等）、风险、路径、关键词、输入输出契约、产物编号、最小命令、验证方式与执行记录、最后验证日期。
- `tool-registry.md` 是由 JSON 自动生成的人读视图，**不得直接手工修改**。
- **修改登记源后的固定顺序**：改 JSON → 运行 `00-工具治理/validate-tool-registry.py`（通过才继续）→ 运行 `render-tool-registry.py` 重建人读视图。
- **先检索后新建**：新建/调整脚本前必须先检索注册表（`find-tool.ps1 -Keyword <关键词>` 或直接读 JSON）。

## 生命周期五态

| 状态 | 含义 | 可否作新任务入口 |
|---|---|---|
| 草稿 | 开发中，未验证 | 不得 |
| 现役 | 已验证，唯一可用态 | 可以 |
| 冻结 | 绑定固定历史输入 | 不得 |
| 历史 | 仅追溯证据 | 不得 |
| 废弃 | 禁止执行 | 不得 |

脚本「仍可运行」不等于可复用。

## 登记判据（满足任一即必须登记）

- 可跨阶段复用
- 生成正式产物或决策证据
- 修改/复制/下载数据
- 需由他人发现、复跑、维护

同一脚本产出多个正式产物时，可登记为多个工具（各自独立 ID 与产物），共享路径的各方须声明同一 `shared_generator`（校验器据此放行，仍拦截未声明的意外重复）。

## 新增流程

1. 用业务关键词检索现有工具，确认不能通过扩展现有工具完成。
2. 在注册表预登记为 `草稿`，写明 ID、范围、输入输出、写入边界、风险、最小命令和验证方式。
3. 按目录边界实现工具，并提供最小使用说明。
4. 完成最小验证；涉及写入时必须验证输出位置、不可覆盖策略和失败后的处理方式。
5. 更新验证日期与生命周期，运行校验和人读视图渲染。
6. 工具移位、弃用、输入输出变化或风险变化时，同步更新登记源、工具说明和关联正式文档。

## 运行约束

1. 凭据、token、私钥和环境配置不得写入脚本、注册表、文档或 git。
2. 数据工具必须遵守 `02-跨目录约束.md` 的保护目录和跨目录写入规则；平台类数据约束按实例规则执行。
3. 工具不得无说明地覆盖既有数据集、快照或正式产物；需要重跑时，应输出新版本目录，或在登记中明确可覆盖范围与回滚方式。

## 临时脚本边界

- 一次性脚本及其日志缓存只放系统临时区：`<系统约定临时根>/<实例名>/<YYYYMMDD>-<任务简称>/`；不登记、不作正式文档长期链接入口。
- 同类临时脚本第二次被需要时：参数化 + 按正式流程登记。

## 配套

- 注册表：`04-工具/tool-registry.json`（模板预登记自带治理脚本 5 条；纯文档实例可清空 `tools` 数组自用）。
- 检索：`04-工具/find-tool.ps1 -Keyword <关键词>`（PowerShell 5.1 兼容）。
- 校验与渲染：`04-工具/00-工具治理/validate-tool-registry.py` / `render-tool-registry.py`（Python 3 标准库，零第三方依赖；实例可自建替代）。校验器中的专用工具目录常量 `ANALYSIS_TOOL_ROOT` 按实例目录结构修改。
- 工作区治理：`04-工具/03-工作区治理/`（挂载同步、续接索引校验）。
