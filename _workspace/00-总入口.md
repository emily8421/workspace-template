# 全局规则总入口

所有进入本工作区的 AI CLI / Agent，先读本文件，再按编号顺序读其余规则；执行任何分析、编辑、整理任务前必须先完成本入口阅读。

## 读取顺序

1. 本文件
2. `01-目录索引.md`（工作区地图：有哪些目录、各自装什么）
3. `02-跨目录约束.md`（保护目录 / 凭据 / 跨目录读写）
4. `03-git管理.md`（仓库拓扑 / 提交约定 / 禁入清单）
5. `04-会话续接.md`（续接机制）
6. `05-落地检查清单.md`（实例化、迁移和目录调整时的自查）
7. `06-AI执行环境.md`（AI CLI 沙箱/权限/审批边界）
8. `07-VSCode工作区挂载登记.md`（涉及 `.code-workspace` 挂载时的唯一真相）
9. `08-通用文档管理原则.md`（A1-A7：事实源/归档/断链/主线程/路径/可追溯/文档语言表达）
10. `09-工具管理.md`（工具注册表/生命周期/临时脚本边界）
11. 当前所在目录的 `AGENTS.md` / `README.md` 与子目录自有规则（如有）

## VS Code 工作区挂载

- `.code-workspace` 的 `folders` 由 `07-VSCode工作区挂载登记.md` 驱动（唯一真相）：改挂载只改登记表 json 块，再运行 `04-工具\sync-vscode-workspace.ps1` 同步。
- 不要手改 `.code-workspace` 的 `folders`（会被下次同步覆盖）；`settings` 等其他字段脚本不动，可自行维护。

## AI 引导机制（AGENTS.md / CLAUDE.md 发现规则）

- 引导不靠 `.code-workspace`（那只是 VS Code 挂载清单）：挂载不会让 AI CLI 自动读到治理规则。
- Codex：读 `AGENTS.md`，以「git 仓库根」为边界，从项目根向下到当前目录逐层找；不在 git 仓库时只检查当前目录。每个目录都要有自己的 `AGENTS.md` 入口并链回本文件（路径用绝对路径）；本治理仓库自身在仓根提供 `AGENTS.md`，保证从 `_workspace` 及其子目录启动也能被引导。
- Claude Code：不读 `AGENTS.md`，只读 `CLAUDE.md`——从启动目录向上逐层查找到文件系统根（跨 git 边界，项目根优先于上层），支持 `@路径` 导入（启动时内联进上下文，建议绝对路径、正斜杠）。因此 Claude 侧需在实例根与本治理仓根各放 `CLAUDE.md` 桥接文件，用 `@` 导入本文件。
- 新目录加入工作区 = 引导三件事：①目录内建 `AGENTS.md`（Codex 用）与 `CLAUDE.md` 桥接（Claude 用，`@` 导入本文件）；②独立 git 仓的入口文件放仓根，非 git 目录仅在「直接以该目录为启动目录」时生效；③登记 `01-目录索引.md` 与 `07-VSCode工作区挂载登记.md`（如需挂载）。

## 新会话第一件事

读 `_handoff/README.md`：若存在相关任务的「进行中」续接文档，先按其中「新会话怎么接」续上，再开始新工作。

## 优先级

子目录规则 > 本全局规则；冲突时先停止相关操作，向用户说明冲突点并等待明确指示。

## 通用执行要求

- 修改文件前确认目标路径未被保护目录或规则限制。
- 批量/整理/格式化脚本必须排除保护目录。
- 凭据（token/私钥）禁止写入任何 git 仓库与文档。
