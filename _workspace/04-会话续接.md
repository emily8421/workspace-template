# 会话续接机制

## 唯一位置

- `<实例根>/_workspace/_handoff/README.md` 是唯一可维护的续接索引和主线程指针。
- 续接文档按目录存入 `<实例根>/_workspace/_handoff/<目录名>/`；跨目录任务放 `共享/`；确认收尾后移入 `归档/`。
- 其他任何 `*/_handoff/README.md` 不得记录主线程、任务状态或索引。为兼容历史路径而保留时，只能包含 `<!-- handoff-redirect: canonical -->` 和指向唯一索引的跳转。

## 命名

`YYYYMMDD-<任务短名>-续接.md`（日期前缀保证排序）。

## 模板

复制 `_handoff/_模板-续接文档.md`。必含小节：日期 / 状态（进行中|已完成|已归档）/ **当前主线或下一任务** / 一句话现状 / 关键位置表 / 核心数字与结论 / 硬约束 / 踩坑记录 / 待办（续接点）/ 新会话怎么接。

## 主线程指针（A4）

- 唯一索引顶部维护「**当前主线/下一任务**」一行。存在主线时，该行必须以 Markdown 链接直接指向状态为「进行中」的续接文档；无主线时写「无」。
- 进行中索引行必须链接到与顶部指针相同的续接文档。每份续接文档的「当前主线或下一任务」字段与之呼应。
- 主线或任务状态变化时，必须在同一变更中更新目标续接文档、进行中索引行和顶部指针。
- 新会话只读取唯一索引，再跟随顶部指针。发现影子索引、目标缺失或状态不一致时，报告 `HOF-001`，不得按续接点开工。

## 索引与生命周期

1. 新文档生成后必须在 `_handoff/README.md` 登记一行：日期 | 任务 | 目录 | 状态 | 路径。
2. 状态流转：进行中 → 已完成（任务收尾时更新）→ 已归档（确认后移入 `归档/`，保留历史不删除）。
3. 每次大任务收尾或主线变化时更新唯一索引；不得以周期性整理替代状态同步。

## 强制规则

- 任务中途或收尾时若未完成，必须生成/更新续接文档并登记索引。
- 任务已完成则更新状态行，不新增文档（除非有新子任务）。
- 新会话进入工作区，先读 `<实例根>/_workspace/_handoff/README.md`。
