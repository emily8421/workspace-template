# 模板同步治理（同步模式 / 流程 / 回流提案）

本文件是模板方法分发的唯一事实源：本实例「跟不跟模板仓同步」以这里为准；同步动作、留痕、回流提案约定都在本文件。

## 同步模式

| 模式 | 含义 | 适用 |
|---|---|---|
| `follow`（默认） | 实例跟随模板仓方法论：模板仓更新后可对实例执行同步 | 希望持续获得新模板方法的实例 |
| `independent` | 独立管理：实例已脱离模板方法分发，同步脚本**拒绝执行** | 团队成员领骨架后完全自主演进的实例 |

- 创建时经 `create-instance.ps1 -SyncMode independent` 选择独立模式；默认 `follow`。
- **切换 = 主动修改下方机读块**（只认本文件 json 块，改别处不生效）：`follow → independent` 随时可改；`independent → follow` 属于重新接入模板方法分发，须用户确认后修改，并同步把 `CHANGELOG-PLAIN.md` 补拉到实例根。
- 每次切换在 `history` 追加一条；模板维护会话与本文件冲突时，以本文件机读块为准。

## 同步设置（机读）

```json
{
  "sync_mode": "follow",
  "updated": "2026-10-27",
  "history": [
    { "date": "2026-10-27", "change": "created", "mode": "follow", "by": "create-instance" }
  ]
}
```

## 同步流程（follow 模式）

1. 更新母本：模板仓根 `git pull`（团队分发走远端；本地仓直接有更新可跳过）。
2. 差异预览：模板仓根跑 `sync-template.ps1 -Instance <实例目录>`（dry-run，不改文件）。
3. 应用：确认后加 `-Apply`；脚本自动在本实例 `_workspace/_同步记录.md` 追加一行（日期 / 模板 VERSION / auto 已同步清单 / manual 实差清单）。
4. 人工合并：按 `_同步记录.md` 里 manual 组的 DIFF 项逐条合并（读模板仓 `CHANGELOG-PLAIN.md` 对应版本段了解「这版改了啥、要做什么」；无关差异可不处理）。注意：实例化过的 manual 文件（目录索引/跨目录约束/挂载登记等含实例内容的）**DIFF 是常态**，不追求清零——只按 CHANGELOG-PLAIN 对照该版本的真实增量合并，没提到的不用动。
5. 回流 triage：见下节；实例 `_回流提案.md` 非空则处理。

## 回流提案（实例 → 模板仓）

实例内干活时发现「这条经验/规则/表单对其他实例也有用」，**当场**写进 `_workspace/_回流提案.md`（格式见该文件内说明），不等定期扫描。模板仓维护会话开头固定动作：收取各实例 `_回流提案.md` → triage（立案/聚合/不立案）→ 处理后清空对应条目。

> 独立模式实例同样鼓励回流：回流是向上贡献，与是否接收下行同步无关。

## 边界

- `sync: auto` 文件模板权威，实例内**不得直接修改**；通用改进走回流提案，实例特例写回对应 manual 文件。
- `independent` 模式下本节全部约束仍然有效，仅「下行同步」停用。
