# AI 执行环境与审批边界

> v0.4 新增：基于 miiot_plugin_develop_system 实例实操归纳。

## 背景

AI CLI（如 Codex）默认在沙箱内运行：可读全部路径，但**写入受限**（通常仅当前工作区与临时目录）。跨目录写入与 git 写操作常见需要用户授权。

## 常见需要用户授权的操作（预期）

| 操作 | 原因 | 建议 |
|---|---|---|
| `git add` / `git commit` / 其他写 `.git` 的操作 | 沙箱拒绝写 `.git` 索引 | 提前说明，可建议批准 `git add`、`git commit` 前缀 |
| 写入 `_workspace` 之外的实例目录（01-文档/04-工具，及按需可选区 02-数据/03-知识输入） | 不在沙箱可写范围 | 确认目标路径与用途后授权 |
| `git push` / 改写远端 | 规则红线：未经用户确认禁止 | 必须逐次确认；新仓首次推送需远端地址 |
| 删除/移动/归档目录（如 D6 收尾） | 破坏性操作 | 必须用户明确确认 |

## 规则

- 写操作先说明目标路径与原因，再请求授权；不绕道其他工具规避审批。
- 只读分析无需授权；批量脚本先声明扫描范围（排除保护目录）。
- 遇到沙箱网络/写权限失败，按「请求授权」流程走，不要静默降级。
