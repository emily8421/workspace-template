# Git 管理机制

## 仓库拓扑（落地时二选一）

| 拓扑 | 结构 | 适用 | 代价 |
|---|---|---|---|
| A 治理独立仓 | `_workspace/` 独立 git 仓；业务目录各自独立仓或按需建仓 | 目录多、数据大、已有多个独立仓（通用推荐） | 多仓管理成本 |
| B 工作区单仓 | 工作区根一个仓管全部，靠 `.gitignore` 排除数据/大文件/凭据 | 目录少、以文档为主 | 全局 `.gitignore` 必须精准，误提交风险高 |

### 选择判据

- 选 A：已有多个独立仓 / 含大型数据与知识输入 / 治理与业务需要独立回滚分享 / 迁移期新旧并存。
- 选 B：全新小工作区、纯文档、无大文件与凭据目录。

## 入仓边界图（拓扑 A 示例）

| 目录 | 是否入仓 | 说明 |
|---|---|---|
| `_workspace/` | 入（独立仓） | 治理规则/索引/续接 |
| `01-文档/`（业务文档） | 入（独立仓） | 文档/需求/方案 |
| `04-工具/`（脚本） | 入（独立仓） | 脚本 + 使用说明 |
| `02-数据/`（可选区） | 不入 | 只登记不存本体；本体在旧目录/外部盘 |
| `03-知识输入/`（可选区） | 不入 | 只读参考；大文件副本不入库 |
| 旧目录（迁移期） | 保持现有仓 | 不 init、不改动、不重提 |
| 数据镜像 / SDK 副本 / E 盘库 | 不入 | 只读 + 大文件 + 可能含凭据 |

> 「提交三仓」≠ 只有三处内容：旧目录已有仓不重提，数据/知识按红线不入库。边界图落地时按实际增减。

## 首次提交流程

1. 各仓 `git init`（逐仓核对，落地清单有对应项；续接文档记录实际 init 状态）。
2. 每仓 `.gitignore`：凭据 / 编辑器状态 / 构建产物 / 数据与知识目录 / 外部盘（按实际）。
3. `git add .` 前检查：staged 中无 `*.zip`、`*.token`、`.env*`、嵌套 `.git`、超大文件（默认 >50MB 不进）。
4. `git commit`：Conventional Commits，`<type>(<scope>): 中文描述`，一次提交只做一件事。
5. `git push` 必须用户确认；新仓首次推送需用户提供远端地址。

## .gitignore 要点（模板见同目录 `.gitignore`）

- 保护目录、原始数据、原始采集、大压缩包
- 凭据：`*.token`、`*.secret`、`*.key`、`*.pem`、`.env*`、`*.log`
- 编辑器/OS 状态：`.agents/` `.claude/` `.cursor/` `.obsidian/` `.trae/` `.history/` `.idea/` `.vscode/` `Thumbs.db` `.DS_Store`
- 构建产物：`node_modules/` `dist/` `build/` `__pycache__/` `*.mpkg`

## 提交约定

- Conventional Commits：`<type>(<scope>): 描述`，中文描述，一次提交只做一件事。
- type：`docs` / `chore` / `feat` / `fix` / `refactor`。

## 禁止

- 保护目录/数据目录内容提交（除非明确允许）。
- 凭据、token 入仓。
- AI 未经用户确认执行 `git push` / 改写远端。
- 对只读下载镜像执行任何写入类 git 操作（push/tag/branch/MR/pipeline 等）。
